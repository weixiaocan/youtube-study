## 存储逻辑审查（本轮只分析，未改代码）

四层存储：`chrome.storage.session` 草稿 → `chrome.storage.local` 的 `records:{videoId}` →
`.claudian/cache/youtube-study/{videoId}/` → Obsidian Vault（笔记 + 附件）。

### P0 会串 / 会丢
- `learning_service.py:219 create_note()` 用「日期 + safe_filename(title)」定位笔记，`if note.exists(): return note`
  不校验归属。同日两个标题相近的视频会共用一份 md，字幕与记录互相覆盖。
- `metadata.json` 的 `notePath` 是 videoId→笔记的**唯一**映射，但 README 声称 `.claudian/cache` 可重建。
  缓存一清，同一视频会再生成一份新笔记。
- 记录的真源在 `chrome.storage.local`，Vault 只是投影。Chrome 数据被清 → 侧边栏归零 → 下次同步整段覆盖 → 批注全丢。

### P1 泄漏
- 截图在 draft 阶段就落盘（`store_screenshot`），但丢弃草稿 / 删记录 / 编辑移除截图都不删文件，无 GC。
- `replace_section()` 降级分支：若「## 完整字幕」标题被改名或删除，会在文末**追加**第二个「我的记录」章节；
  此后 marked 正则永远只命中第一对标记，新章节再也不更新。

### P2 一致性
- `records.json` 只写不读（grep 确认无读取点），是死数据。
- `ThreadingHTTPServer` + 无锁读-改-写，与 Obsidian 并发编辑是 last-write-wins。
- `saveDraft()` 用 `draft.videoId`、`deleteRecord()` 用 `state.video.videoId`；SPA 内切视频时 tabId 不变而
  draft 保留上个视频的 videoId，会把 B 的 records 写进 A 的键。
- `content.js` 的 `loadTranscript()/parseJson3Transcript()/parseXmlTranscript()` 与 background 的
  `FETCH_CAPTION_TRACK` 是死代码；实际只走 yt-dlp，且硬编码 `--sub-langs en-orig,en`。
- README 说草稿存「Chrome 本地存储」，实际是 `chrome.storage.session`（关浏览器即丢）。
- 二次按 Alt+N（`background.js:138`）会静默丢弃上一条未保存草稿，只 resume 播放，无提示。

## 用户确认的需求边界
- **笔记以 video_id 为唯一主键**，一个视频只允许一份笔记，不因日期产生多份。
- **单向同步**：界面修改 → 同步到 Vault。用户在 Obsidian 里手改 = 已进入加工阶段，反向同步需求低，不做。
- **截图必须挂在笔记上**，孤立截图无意义，需要能被清理。
- **字幕缓存复用**（已获取过就不再下载、直接读缓存）是预期行为 ——
  这条**已经实现**：`content.js restoreCachedTranscript()` → `load_cached_transcript()` 走纯缓存路径，不下 yt-dlp。
  需要区分的是：字幕缓存可重建 ✓，但同目录下的 `metadata.json:notePath` 映射不可重建 ✗。

## 拟定的改造方案（待用户拍板后动手）
1. 新增 `find_note_by_video_id(vault, video_id)` 扫 frontmatter 反查；`create_note` 前先反查，命中即复用。
   这一步做完，缓存清空后仍能找回旧笔记，不产生重复文件，且**零迁移**。
2. 新笔记文件名加 `— {videoId}` 后缀防同日碰撞；老笔记不改名。
3. 截图 GC：`cache/screenshots/` 是原件库（`materialize` 是 copy 非 move，删原件则附件无法重建）→ 保留；
   `原始材料/_附件/youtube-study/{videoId}/` 是派生物 → 在 `sync_records` 里按 records 引用集合清理孤儿。
4. `replace_section()`：分支3 拆成「有 `## 我的记录` 就插其下 / 无则才追标题」；分支1 先归并多余标记对。
5. `records.json` 升级为真源（host 端存 + 侧边栏恢复），避免 Chrome 数据被清时批注全丢。
